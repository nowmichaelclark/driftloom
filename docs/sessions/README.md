Thirty-two hands sessions and five brain sessions. Sessions 25 (the Android
shell) and 19 (the FLAC writer) touch nothing the others do until they
merge, so either may run alongside another session if you want to save
days; everything else runs one at a time, because each takes the next
version number and rebuilds the same `.wasm`.

**Why this many.** Batch 6 is fourteen approved sounds across five parts of
the core; one or two a session keeps each PR measurable. Long pieces get
six sessions on purpose (Mikey, 2026-11-10: the composing for the longer
lengths done really well): a plan first with nothing audible, each journey
on its own, the themes apart from the energy, the joins last, and one more
after his ears. Android is five because the native audio, the bridge and
the background service each fail in their own ways.

## Rules for every session

Every hands prompt points here. These come on top of `AGENTS.md`, the
queue's standing rules and merge policy, and `core/AGENTS.md`.

- **Check your place first.** Every row above yours should be ticked,
  except rows the table says may run meanwhile. If one isn't, stop and say
  so: don't do another session's work.
- **One PR per item** (or per sub-item), from the latest `main`, on the
  branch the session was given. Take the next version number from `main`
  and bump `BUILD` (`js/main.js`) and `CACHE` (`sw.js`) together on every
  app change.
- **Before each item,** look at `nightly.yml`'s latest run on `main` and
  fix a red one first. Never wait on the nightly.
- **Merge under the policy:** `tools/gate.sh` green locally, the `core` and
  `docs` workflows green in CI, and every check the prompt names passing.
  Then merge your own PR and go on. Red or unfinished: don't merge, say
  what fails.
- **Measured, not guessed.** Where a musical choice is open, take the
  conservative option, write it in the PR and mark it "for Mikey's ears".
- **Don't stop for Mikey.** Anything that needs his ears, his phone, his
  accounts or a decision is one line in `docs/notes/for-mikey.md` (what,
  which PR, what to listen for or decide), and the work moves on. Device
  checks merge on the policy; a revert follows if he finds trouble. Stop
  an item only for a decision that can't be undone and could go either
  way: leave `docs/notes/<item>-<name>.md` and end the session there.
- **Don't overreach.** Do this session's work and stop. If it turns out
  too big, finish a clean part, merge it, and write what is left at the
  top of your file in this folder (a "Left" list), so the next session
  with the same prompt picks it up.
- **When you finish:** add each merged PR's line to `docs/DONE.md` (in the
  session's last PR, or the next session's first), keep the queue's status
  line current, tick your row in the table above, and end with a plain
  summary for Mikey: what merged (PR numbers), what to listen for, what
  waits in `for-mikey.md`.
- **The nightly first.** The slow renders hold no merge, so a sound change
  can leave the nightly red unseen (#361 did; session 03 fixed it in #366).
  Before your item, look at the latest nightly run
  (`.github/workflows/nightly.yml`); if it is red for a reason in the code,
  fix that first, as its own PR. A PR that moves the core's sound updates
  the stored render hashes it moves, in the same PR.
- **The tablet's margin.** Mikey's Lenovo tablet, the weakest device he
  supports, has about 1.8 times headroom on lite before item 100's
  too-slow line (its busiest quarter-second about 55% of its time;
  `js/quality.js`). Anything that adds work on the audio thread (a voice, a
  block, a section line's making) reports the baseline's costs and keeps
  them within 5% unless the PR says why; spread new making across blocks
  as a load is.
- **The app's name from one place.** The app is renamed at 1.0 (session
  31a). Write its visible name and address from one place (the page's name
  constant and the manifest; Android's one resource; fastlane's title),
  never into new text where the rename would have to hunt for it, and never
  into the code format (session 22).
- **The long pieces hold** (brain B3, 2026-11-14: Mikey kept them as they
  are). A sound change that moves what a loop plays (a note, a hit, a
  velocity: not a width or a tone) runs the full `node tools/longform.mjs`
  (about an hour; the joins' hole yardstick, the endings and the arcs as
  played) and keeps every check it kept on `main`; the joins read the kit
  (a fill is the loop's own snare or rim, a floor out its kit and bass), so
  a new kit is heard there too. Say in the PR what moved.
- **Sound items** name, in their Done line, two corpus loops (corpus seed
  20261009) that draw the new sound, with a time, so the brain can build
  the album without searching.

Things earlier sessions learned:

- A line added above shipped Rust code changes `js/dlplayer.wasm`'s bytes
  even when it is compiled out (`core/AGENTS.md` says how to avoid it).
- `tools/measure.mjs`, `tools/baseline.mjs`, `tools/stats.mjs`,
  `tools/gen-golden.mjs`, `tools/dials.mjs` and `tools/octave.mjs` run in
  Node on the core; several need `tools/build-core.sh --tools` first
  (`tools/gen-lib.mjs` reads everything the generator decides).
- The generation goldens' file (`core/golden/generation.hashes`) is the
  list of cases: a new case is a line of its first three fields, and
  `node tools/gen-golden.mjs` writes the hashes.
- `tools/rows.mjs` checks every app control in about a minute, from a fixed
  first loop (session 01: ten runs in a row, ten passes).
- The local gate takes about 35 minutes (the core's tests are slow in a
  debug build); CI runs the same parts side by side in about ten. Push
  early so both run at once.
- **On Mikey's own machine** (from session 02, 2026-11-11, Fedora): Rust is
  in `~/.cargo` (`export PATH=$HOME/.cargo/bin:$PATH` in the command if
  `cargo` isn't found), and git has no identity there: set it on each
  commit (`git -c user.name=Mikey -c
  user.email=162073748+nowmichaelclark@users.noreply.github.com`), as
  main's commits are, and change no settings. Force-pushes are refused:
  plan one PR per branch from the start.
- Album codes: `js/share.js`'s `encodeAlbum(title, specs)` with specs from
  `js/gen.js`'s `newSpec(seed, request)` (in the page) or `decodeSong(code)`;
  in Node, `tools/gen-lib.mjs`'s `newSpec` and `render` read the tools'
  build. Round-trip with `decodeAlbum` before giving a code to anyone.
- The long pieces' plan (session 11): `dlgen --map SEED REQUEST` prints a
  piece; `node tools/longform.mjs` runs the corpus checks in about two
  minutes (2,400 pieces); `core/tests/longform.rs` is the
  gate's copy. The plan is not linked into `js/dlplayer.wasm` until
  something plays it, so session 12's first use will grow the module.
- The wander is heard (session 12, `core/src/generator/heard.rs`): a pass
  carries its section's plan (`Pass::heard`); an arc's hears nothing yet
  (session 13 hears it the same way). `node tools/longform.mjs` now plays
  wander pieces through `dlrender` and checks what is played (about ten
  minutes; `--plan` for the plan alone). The app's module grew 53 KB once
  the plan was linked in. In a cloud session GitHub's API may be closed to
  the session while a pasted token still pushes: then the PR is Mikey's to
  open (session 12).
- An arc is heard too (session 13, `heard::Lift`): its energy as marks and
  levels, measured against the loop as itself (`tools/longform.mjs`, about
  an hour with its arcs; `--arcs 10` for a quicker look). A finite arc's
  last bars land (`heard::Landing`): session 14's keys must keep it on the
  home key.
- An arc's themes and keys are heard (session 14, `heard::Lift::themed`):
  a section plays one tune beside the loop's own (`heard::Tune`), which the
  generator makes a stage a block before the section's pass is drawn
  (`Generator::prepare`; anything that draws a pass straight calls it
  first). Every pitch is made in the home key and moved by the unit
  (`heard::Unit::moved`): a new pitched thing in the sequencer goes
  through it too. `node tools/longform-themes.mjs` (about eight minutes)
  measures the themes on what is played; `dlgen --map SEED REQUEST
  --movements` prints a line a movement and `dlgen --theme-cost` times a
  theme-B section. Session 15's joins: `Span::changed` says what a line
  changes; nothing is written across a key's or a theme's line yet but
  the return's held fifth.
- The joins and the slider's close (session 15): `Form::join_of` chooses a
  unit's join, `Form::joined` gives it to the map, and `heard` reads it
  from the units a section already has (so a section costs what it did);
  `Heard::stop_at` plays the close the length slider asks for. `dlrender
  --track bars=N` plays a piece with the slider set, the core's own next
  loop after, as the app does; `tools/longform-clips.mjs` makes the
  listening set again from the maps (`--before` a dlrender from dfe78c3 for
  the blind pairs). `tools/stalls.mjs --loops arc,arcs` is the stall test
  on an arc of 32,768 bars and on Endless arcs.
- There is one generator and one engine, the core's (item 97). A change to
  what is generated is made once, in `core/src/generator/`, with its data
  in `data/*.txt`; the page only reads.
